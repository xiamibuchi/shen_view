# 实例模式

设置 → 通用可选择单进程或多进程。单进程复用最近使用的存活窗口；多进程每次启动独立窗口，
并显示“新建窗口”和“在新窗口打开”。切回单进程不强制关闭已有窗口，只影响后续启动。
文件选择器和拖放始终打开到当前窗口。

启动时多个路径在单进程中依次打开，最终停在最后一项；多进程中每项独立打开。
无路径时遵循 [最近打开与恢复规则](window-and-file-operations.md#打开与最近记录)。

## 启动与文件交付

每个进程在配置目录注册动态 loopback TCP 端口及随机令牌，并持有活动文件锁。
启动锁覆盖模式读取、已有窗口选择和新实例注册，防止同时冷启动重复创建单进程窗口。
进程崩溃后由系统释放锁，后续启动回收失效端点，不需要常驻主控进程。

文件请求在查看器初始化后串行处理，转发成功表示已入队；实际打开失败仍由查看器提示。
连接存活实例失败时报告启动错误。Windows 转发前授予目标前台激活权限；
macOS 通过 AppDelegate 接收文件事件，通过 NSWorkspace 创建独立实例。
Finder、NSWorkspace 和沙箱权限仍需 macOS 实机验证。

## 共享数据

设置、阅读进度、最近打开与最近颜色共用配置存储：

- 进程内队列和跨进程锁覆盖读取最新配置、合并、提交的整个事务。
- 写入使用同目录唯一临时文件，刷新后原子替换，不先删除旧配置；普通读取取得完整的新旧快照。
- 设置仅合并实际变更字段，阅读进度按对象合并，最近记录按操作合并；不将旧窗口快照整份写回。
- 未变更及未知字段保留。其他窗口不主动切换设置，下次启动读取最新配置。
- Windows 共享冲突限时重试。严格读取失败时不允许把空配置用于覆盖已保存的数据。

压缩包缓存另有跨进程维护锁、共享租约和密码包私有目录；维护锁覆盖解压，可能使其他窗口等待。
失焦只减少预载，不清空已显示的内容。

[开发说明](../development/getting-started.md#配置存储与排查)，验证入口见
